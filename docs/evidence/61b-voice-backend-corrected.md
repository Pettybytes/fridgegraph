# Evidence 61b — Browser voice backend, CORRECTED (audio in, one call)

**This file is an append. `61-voice-backend.md` and `61-voice-backend.json` are preserved unchanged**
— the 7/8 run and its `ASR 502` failure stay exactly as recorded, because that is what happened.

## What was wrong

The batch endpoint was reachable and authenticated, but three separate things were wrong at once:

1. the `request` part was sent as a plain form field — the API needs a **`application/json` part**;
2. `mode` was missing — the documented body carries **`"mode": "PUSH_TO_TALK"`**;
3. the audio was **MP3 bytes relabelled `audio/wav`** with `"audioEncoding": "WAV"`. That is not a
   conversion, and `input.wav` under a second name is exactly what "Malformed request" was telling
   me.

Baseline reproduced first, before touching the server:

```
POST https://api.meta.ai/v1/asr/transcribe
Authorization: Bearer <key>          Accept: application/json
part "request"  application/json  {"model":"muse-voice-transcribe-1.0","audioEncoding":"WAV","mode":"PUSH_TO_TALK"}
part "audio"    audio/wav         genuine mono PCM16 WAV (ffmpeg: -ac 1 -ar 16000 -acodec pcm_s16le)

200 {"transcript":"testing the fridge graph voice channel.","audioDurationMs":2000}
```

## What changed

`ops/voice-turn-server.mjs` — the adapter, not the design:

- the `request` part is a real `application/json` Blob carrying `model`, `audioEncoding: "WAV"` and
  `mode: "PUSH_TO_TALK"`; `Accept: application/json`;
- **`toPcm16Wav()`** converts whatever the browser recorded into a genuine mono PCM16 WAV
  (16 kHz) with ffmpeg, and **validates the result by parsing the RIFF/fmt chunks** (`format 1`,
  1 channel, 16-bit, 16 or 24 kHz). A clip that is already acceptable is passed through untouched;
- if ffmpeg is absent or the conversion does not produce real PCM, the route fails with
  `415 ASR_UNAVAILABLE` and the reason — it never sends something the API will reject and never
  invents a transcript. The transcript field is read from `body.transcript` (what the API actually
  returns), with `text` kept as a fallback;
- the multipart boundary is generated by `FormData` and never written by hand.

Unchanged on purpose: the caller's own bearer is still the only identity, forwarded through Rosina to
MCP; `ELEVENLABS_API_KEY` and `META_API_KEY` stay server-side; both routes are still 12/min per
caller.
