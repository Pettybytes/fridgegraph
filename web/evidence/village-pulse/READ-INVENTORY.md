# Village pulse read inventory — before implementation

All graph reads use the signed-in perspective's in-memory bearer through the existing Apollo client and `runRead`. `coordinationJobs(childId)` is filtered by the caller's database RLS; `attempts(jobId)` is RLS filtered; `jobTimeline(jobId)` returns no entries for an invisible job. `orbitStatus(childId)` is likewise caller scoped and returns the latest visible alert's safe status fields. The UI must refuse non-parent perspectives rather than treat an authorization failure as an empty village. No shared stack was queried for this inventory.

| Proposed panel | Existing read and fields | Window and calculation | Decision |
| --- | --- | --- | --- |
| Coverage | `coordinationJobs` gives `id`, `status`, `idempotencyKey`, evaluations and confirmation; `jobTimeline` gives `JOB_CREATED` time. Calendar reads do not link a care requirement, its needed coverage period, and a completed outcome to a job. The key is not a public request-date field. | No defensible covered/pending/uncovered denominator or upcoming-request date exists. Show caller-visible requests **created** in the displayed Detroit date window with their recorded statuses. Do not classify a calendar gap, silence or absent confirmation as uncovered. | No coverage percentage or covered/pending/uncovered chart. Recent requests only. |
| Request funnel | `coordinationJobs(childId)` IDs, `type`, current status and confirmation; `attempts(jobId)` IDs and dispatch `at`; `jobTimeline(jobId)` has `JOB_CREATED` at. The existing job query is extended to select the already-defined `type` field. | Cohort: distinct visible **PICKUP** jobs with a recorded `JOB_CREATED` on the last 30 Detroit calendar dates, inclusive. Count distinct jobs in the cohort; then independently count jobs with at least one recorded attempt and jobs with a recorded parent-approval confirmation. These are job counts, not attempt counts or verified pickups. Jobs without creation time cannot enter this dated cohort. | Supported as three clearly named counts, with no conversion claim. |
| Response time | `attempts` exposes dispatch `at`, `closedAt`, `closedReason`; evaluations expose `acceptedVia` but no reply instant. `jobTimeline` has attempt opened/closed and parent `CONFIRMATION`, but no caregiver response event. | A duration requires dispatch and the matching caregiver response time. Attempt closure or timeout is not a response. No sample size or duration can be calculated. | Unavailable read gap; never substitute close or approval time. |
| Open items | Jobs expose current `status`; `awaiting_approval` is explicitly waiting on a parent under `docs/contracts/pickup-job.md`. The Orbit controller's existing `orbitStatus` read exposes `alertId` and `status` for the **latest visible** alert. | Current caller-visible items, not a historical window. Show pending-approval jobs and the latest active Orbit status only. Link to Mission Control and Orbit. No alert message, photo, place, descriptors or controls. A null latest status cannot prove that no older active alert exists. | Supported with the latest-alert limit stated. |

The dates and cohort are displayed in `America/Detroit`. A stored demo record is labelled as such. Each panel has its own loading, empty, refused and failed handling; an unavailable measure is never rendered as zero.
